# 行为评估协议

`cases.json` 是**期望行为规格**，并不表示已实际调用生图模型测试。

## 逐条运行

1. 在装有 `visual-art-director` 的 Agent 中新建干净对话；为每个测试案例提供其 `request`。有图案例要配合足以判断角色的真实样例图；否则只评估路由文字，不评估图像保真。
2. 要求 Agent 输出精简决策摘要（路由、各输入图作用、主风格、保留要素、禁止项），先不要调用生图工具。
3. 对照 `expected_route`、`expected_style`（为 `null` 表示允许自主判断或不应启用）、`required_evidence` 和 `guardrail` 打分。
4. 仅对路由通过的创作案例进行真实出图；另按 `references/quality-gates.md` 由人或独立视觉评估 Agent 检查。
5. 记录 FAIL 的具体原因，调整触发描述或参考文档；更新版本并复测。

## 评估维度

- 路由正确：必须。
- 原图角色正确：必须（有图任务）。
- 不该改的元素得到明确保护：必须。
- 选择风格有根据：主观审美不能凭独立测试断言“唯一正确”，可以评价是否明显跑偏。
- 真正执行时结果满足视觉要求：必须人工/视觉检验，**不能**用脚本静态检查替代。

## 数据隔离

`cases.json` 的 `expected_style` 只是设计上的合理基线，不是用户明确指定风格时的替代规则。比如“画一座中国山城”没指风格，水墨是合理基线，但出于具体用途选择工笔或古典雕刻也可能合理；不可把这个基线当作绝对真值。
