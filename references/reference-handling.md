# 上传图处理协议：图片扮演什么角色？

## 1. 先做图像角色表

对每张上传图，按**用户语言和可观察的图片信息**提取以下字段：

| 字段 | 应记什么 |
|---|---|
| id | 图 1 / 图 2 / 源附件编号 |
| role | `base`（编辑底图）/ `subject`（主体）/ `style`（视觉语言）/ `layout`（构图）/ `palette`（配色）/ `material`（材质）/ `accessory`（局部元素） |
| observed | 实际看得到的可验证特征，不猜图外内容 |
| locks | 不得改变的部分 |
| freedoms | 可以改动的部分 |
| conflicts | 与其他源图冲突之处 |

**一张图允许多个角色**；如果用户说“第一张人物、第二张构图、第三张画风”，三者角色不得互换。

## 2. 用户常用语义解码

- “参考这个风格”“像这个画风”“这种线条感”：`style`，默认不承袭原图建筑、人脸或布局。
- “这个人”“这个Logo”“这款产品”：`subject`，身份/形状/已指定视觉特征要保留。
- “沿用它的构图”“同样机位”：`layout`，保留空间关系，换成用户所要求内容。
- “只换颜色”“按第二张配色”：`palette`，保留颜色关系不是借用第二图主体。
- “把这张图变成……风格”“原图改成……”：`base + TRANSFORM`，保留主体、身份、动作、布局。
- “修掉……”“添加……”“其他不变”：`base + LOCAL-EDIT`，最小改动。
- “将 A 放到 B 里”“两个人合影”“两图合成”：`COMPOSITE`，A/B 分别源和目标场景。

## 3. 保真层级

### L3 高约束（变化局限于授权区域）

适用于精确局部修改、产品图、人物保真、已有 Logo、图标体系：

- 写清必须保留：主体外观、相对位置、光照方向、背景及独特特征中哪些被锁定；
- 修改范围仅限用户指定部位；
- 如果没有编辑工具/遮罩，明确像素一致无法保证；
- 对母标、已批准字体排版、精确文字优先复用可用源资产或原图，而不是重新生成。

### L2 中约束（内容保持、画风变化）

适用于照片变版画、素描变摄影、风格迁移：

- 保留主体数量、姿态、面部/造型要点（确能观察到的）、关键建筑与层次；
- 改变媒介、光色、笔触和局部装饰；
- 允许表现方式改变，不凭空增加妨碍认出的新主体。

### L1 弱约束（借鉴参考）

适用于参考照片创造新场景、从几张风格参考提炼共同视觉语言：

- 只取用户授权的维度：如颜色、光感、笔触、构图规律；
- 可以创造新主体/场景/机位；
- 不默认复刻原图的偶然元素。

### L0 无来源约束（自由创作）

适用于纯文字生图。以用户文字、用途与可验证需求为唯一依据。

## 4. 冲突处理

1. 用户的显式图片分工优先于助手猜测。
2. 若两张来源都定义同一属性，优先用户最近明确的要求；没有明确优先级时，选择与主要目标匹配者并在必要时说明。
3. 来源图的背景文字、水印、人物、标志未被指定继承时，不自动加入新图。
4. 如果照片被要求转成插画，禁止“相机像素级保留”和“整体重构”同时承诺。
5. 多图冲突强且结果无法推进时，只问**一个真正阻断的问题**；否则作合理最小假设并执行。
6. 当前模型无视觉读取能力时，不推断“看过/分析过”图片；向用户说明无法准确提取保留要素。

## 5. 场景示例

### 图1是画风样本，用户要求“生成一座全新的中国山城”

`REF-CREATE`；保留细密排线、防伪曲线、双色油墨、纸张质感；**不保留**原始图的具体城镇、建筑数量、地理位置或机位。

### 图1是用户家猫，要求“只把沙发换成木椅”

`LOCAL-EDIT`；猫的毛色、姿态、眼睛、镜头和室内其他部分锁定，改动限于沙发及合理接触阴影。

### 图1产品、图2摄影棚布光

`REF-CREATE` 或 `COMPOSITE` 取决于是否要求直接合成已有照片。锁定产品标志/比例/配色，从图2仅借用柔光布光和背景调性。
